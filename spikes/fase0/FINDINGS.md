## Update — fix 48 kHz + Fish Audio (controlador, 2026-08-15, con API keys del usuario)

**Fix de audio 48 kHz (resuelve el bloqueante de Task 4/5).** En Pipecat 1.7.0 el output auto-resamplea pero el **input NO**; por eso 16000 fallaba con device WASAPI (`-9997`). Solución: toda la pipeline a **48000** (transport `audio_in/out_sample_rate=48000` + `AssemblyAISTTService(sample_rate=48000)`, que AssemblyAI acepta, 8k–96k). Resultado tras el fix:
- **Task 4** (`03_audio_wasapi.py` @48k): loopback abre y corre 8 s **sin `-9997`**. Falta que el usuario hable para juzgar el eco.
- **Task 5** (`04_stt_assemblyai.py` @48k): el mic captura **Audio Duration=20.0s** (antes 0.0s) + AssemblyAI conecta y acepta español. Falta que el usuario hable español para juzgar la **calidad** de transcripción.
- Regla confirmada: al pinear un `*_device_index` WASAPI, el rate del transport DEBE ser el nativo del device (**48000**); 16000 → `-9997`. Sin device index explícito, el device por defecto (MME) resamplea y 16k "funciona".

**Task 6 TTFA — medición WARM (cliente persistente) + 48k.** TTFA total (query→primer audio) = **2.738 s** warm (vs 6.922 s cold). TTS ElevenLabs: TTFA(TTS) 0.666 s / TTFB 0.572 s. ⇒ **ni warm se alcanza <1.5 s** para la RESPUESTA (Haiku ~2 s a la primera frase); el <1.5 s solo se logra vía **relleno hablado**. El TTS no es el cuello de botella.
